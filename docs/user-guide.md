# Руководство пользователя

## Вход

URL: http://localhost:8080 (или ваш хост nginx).  
Учётные данные по умолчанию после `make seed`: `admin` / `admin123`.

## Дашборд

Главная страница с настраиваемыми виджетами.

### Фильтры и экспорт

- **Сценарий** и **Период** — в одном ряду над виджетами, всегда видны: сценарий слева,
  период прижат к правому краю. При выборе «Свой период» слева от него появляются поля «С» и «По».
- **Экспорт** — иконка загрузки в шапке рядом с карандашом; по клику выбор формата **CSV** или **JSON**.
  В файл попадают текущие фильтры: в JSON — блок `filter_summary` (период, сценарий и т.д.),
  в CSV — комментарии `#` в начале файла с теми же полями.
- **Карандаш** — режим конструктора: добавление виджетов, размер, перетаскивание, сохранение layout.

### Размеры виджетов

Сетка **4 колонки**; размер задаётся двумя числами в редакторе виджета:

| Параметр | Диапазон | Значение |
|----------|----------|----------|
| **Ширина** | 1–4 | 1 = ¼ экрана, 2 = ½, 3 = ¾, 4 = на всю ширину |
| **Высота** | 1–2 | 1 = стандартная, 2 = высокая (две строки сетки) |

При выборе метрики конструктор подставляет рекомендуемую ширину и высоту; их можно
изменить вручную. Старые layouts с пресетами `small` / `medium` / `large` при загрузке
мигрируют автоматически (1×1, 2×1, 4×2).

| Для чего | Ширина × высота | Примеры |
|----------|-----------------|---------|
| KPI, счётчики | 1×1 | Всего звонков, средний балл, покрытие |
| Статистика, сравнения | 2×1 | Длительность, динамика балла |
| Рейтинги операторов | 2×2 | Топ-5 лучших / худших |
| Графики, темы, heatmap | 4×2 | Распределение оценок, классификация тем |

Высота только ×1 или ×2 — в одном ряду карточки выравниваются по сетке. Лишнее содержимое
прокручивается внутри виджета.

- Типы виджетов: количество, KPI, статистика, проценты, графики, рейтинги, динамика, тепловые таблицы, сравнения
- Данные: звонки, оценки, длительность, операторы, критерии, темы

## Звонки

### Список

Фильтры, сортировка, оценка (бейдж), статус обработки.
Внизу — пагинация и селект **«На странице»** (20 / 50 / 100) в общем стиле контролов.

**Экспорт** — иконка загрузки в шапке (как на дашборде), форматы **CSV** / **JSON**.
В файл попадают поля таблицы плюс тема, резюме, исход звонка и теги (без транскрипта).

- Если в таблице есть **выделенные** звонки — файл скачивается сразу по выбранным id.
- Если ничего не выделено — после выбора формата открывается модалка фильтров
  (префилл с текущих фильтров списка). По «Экспорт» создаётся фоновая задача; когда файл
  готов, начинается скачивание. Лимит выборки — 5000 звонков.

### Карточка звонка

Три колонки:

1. **Сводка** — оценка, резюме LLM, боли клиента, итог, чек-лист по критериям, теги, заметки супервизора
2. **Аудио и транскрипт** — waveform, плеер, диалог (клик по реплике → перемотка), подсветка триггерных слов
3. **Действия** — повтор ASR / повтор LLM

Статусы обработки отображаются в шапке; при `transcribing` / `analyzing` страница обновляется автоматически.

## Операторы

Список операторов с количеством звонков и средним баллом.
Пагинация показывается только если в списке есть записи.

Кнопка **«Обновить список операторов»** подтягивает операторов из истории звонков Webitel
за последние 7 дней (нужен настроенный коннектор). Запрос выполняется сразу, кнопка
показывает «Обновление…», а под шапкой появляется результат:

- «Добавлено операторов: N» — список обновлён автоматически;
- «Новых операторов нет» — все найденные операторы уже есть в базе;
- красный текст с причиной, если Webitel не настроен или недоступен.

## Сценарии и критерии

### Список сценариев

Создание, копирование, экспорт JSON, удаление.

### Редактирование сценария

- Название, модель LLM, флаг «Активен»
- **Системный промпт** — общая инструкция для оценки
- **Критерии** — перетаскивание порядка; для каждого: ключ (латиница), название, вес %, макс. балл, промпт критерия

Сохранение — кнопка «Сохранить изменения» внизу (появляется при изменениях).

## Плейграунд

Тестирование без влияния на production до явного сохранения.

1. **Создать сессию**
2. Выбрать **сценарий оценки**
3. Промпт: из сценария или свой тестовый
4. Загрузить файлы (drag & drop или выбор)
5. **Запустить анализ** — прогресс по файлам
6. Открыть готовый файл: оценка, чек-лист, аудио, транскрипт
7. При необходимости — **Сохранить в общую базу звонков**

При зависании на «Распознавание ASR» — снова **Запустить анализ** (сбрасывает очередь ASR) или перезапуск `celery-worker`.

## Исследования (LLM метаанализ)

Раздел для **сводного анализа** группы звонков по произвольному промпту (не оценка по сценарию).

| Per-call QA | Исследование |
|-------------|--------------|
| Сценарий + критерии | Свободный промпт |
| JSON с баллами | Markdown-отчёт |
| Один звонок | Выборка по фильтрам |

### Создание исследования

1. **Исследования** → **Новое исследование**
2. **Название** — для списка и истории
3. **Промпт** — вопрос к LLM по выборке (например: «Какие основные жалобы клиентов в марте?»)
4. **Фильтры:** период дат, направление (входящий/исходящий), оператор
5. **Проверить выборку** — сколько звонков с транскриптом попадёт в анализ (макс. 200, настраивается через `RESEARCH_MAX_CALLS`)
6. **Запустить анализ** — фоновая задача Celery
7. Открыть исследование — дождаться статуса «Готово» и прочитать Markdown-отчёт

### Важно

- В отчёт попадают только звонки **с готовым транскриптом** (статусы `transcribed` / `analyzed`)
- LLM, PII-маскирование — из **Настройки → Модели и AI**
- При большой выборке анализ может занять несколько минут (несколько вызовов LLM)
- **Экспорт:** на странице готового исследования — «Скачать Markdown» / «Скачать JSON»; в списке — иконка загрузки

Подробнее: [research.md](research.md).

## Настройки (admin)

| Вкладка | Содержание |
|---------|------------|
| Модели и AI | ASR, LLM, PII, производительность ASR |
| Качество | Пороги оценок, таксономия тем, обслуживание |
| Коннекторы | Webitel API и БД |
| Автоматизация | Расписание, batch_size, сценарий |
| Пользователи | Учётные записи супервизоров |

### Качество

- **Пороги качества** — границы зелёного / жёлтого / красного и целевой балл для графика динамики.
- **Таксономия тем** — список категорий, из которых LLM выбирает тему звонка.
- **Классифицировать без темы** — проставить тему звонкам без классификации (например, если
  LLM был недоступен во время анализа).
- **Восстановить зависшие звонки** — вернуть в очередь звонки, надолго застрявшие в
  «Транскрибация» или «Анализ» (например, после перезапуска worker). Звонки, которые
  обрабатываются прямо сейчас, не затрагиваются; то же делает автоматическая проверка каждые 10 минут.
