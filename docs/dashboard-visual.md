# Дашборды: внешний вид

Документ описывает **визуальный язык** дашбордов CCSA — как они должны выглядеть.
Состав виджетов и метрики разбираются отдельно (см. будущий `dashboard-composition.md`).

Основано на анализе 5 референсов (производство, медицина, крипто-портфель,
проект-менеджмент, e-commerce). Несмотря на разные домены, у всех единый паттерн.

---

## 1. Общее впечатление

- **Тёмная, «приборная» эстетика.** Глубокий тёмный фон, на нём — карточки чуть светлее.
  Ощущение control room / пульта, где данные светятся на тёмном.
- **Один яркий акцент.** Вся палитра нейтрально-серая, цвет только у акцента и семантики
  (красный/оранжевый в 3 из 5 примеров — совпадает с нашим `--red`).
- **Данные — главный герой.** Крупные числа, приглушённый «обвес» (подписи, сетки, оси).
- **Плотная, но дышащая сетка.** Много виджетов, но за счёт единых отступов и выравнивания
  не выглядит захламлённо.

> Наша текущая тема — светлая с charcoal-акцентом. Референсы тёмные. Дашборд должен быть
> **первоклассным в обеих темах**. Проектируем от тёмной (там плотные приборные экраны
> смотрятся выигрышнее), но сразу закладываем светлый вариант — см. раздел 11.

---

## 2. Каркас страницы (layout)

Единая структура во всех примерах:

```
┌────────┬─────────────────────────────────────────────┐
│        │  Topbar: заголовок · поиск · период · профиль │
│ Sidebar├─────────────────────────────────────────────┤
│  (nav) │  KPI-ряд: 4–5 компактных карточек-метрик       │
│        ├───────────────────────┬─────────────────────┤
│        │  Крупный график        │  Вторичный виджет    │
│        │  (line / bar / heatmap)│  (donut / list)      │
│        ├───────────┬───────────┼─────────────────────┤
│        │  виджет    │  виджет    │  виджет / таблица    │
│        └───────────┴───────────┴─────────────────────┘
└────────┴─────────────────────────────────────────────┘
```

- **Sidebar** — узкий, иконка+подпись, активный пункт подсвечен «таблеткой» (заливка/бордер).
- **Topbar** — приветствие/заголовок слева, справа: поиск, селектор периода, уведомления, аватар.
- **KPI-ряд** — всегда первый по важности, узкие равновысокие карточки в один ряд.
- **Основная зона** — гибкая сетка (12 колонок), виджеты разной ширины (1/4, 1/2, 3/4, full).
- **Правая колонка** — часто «второстепенная»: списки, топы, статусы (уже основной зоны).

---

## 3. Карточки

Базовый строительный блок. Общие черты:

| Свойство | Как выглядит |
|----------|--------------|
| Фон | На 1 ступень светлее фона страницы (`--surface` над `--bg`) |
| Граница | Тонкая `1px` полупрозрачная, либо вовсе без неё (разделяет только фон) |
| Скругление | Заметное, 10–16px (мягче, чем у наших контролов 6–8px) |
| Отступы | Внутренние 16–20px, между карточками 12–16px |
| Тень | Почти нет; глубина создаётся контрастом фонов, а не тенями |
| Заголовок | Мелкий приглушённый текст сверху + опционально меню «⋯» / селектор справа |

Иерархия трёх слоёв по светлоте: **фон страницы → карточка → вложенный элемент**
(мини-плитка, строка, чип).

---

## 4. Цвет

**Принцип: нейтральная база + один акцент + семантика.**

- **База:** 3–4 оттенка серого (фон, карточка, вложенный блок, границы).
- **Текст:** белый/светлый для значений → серый для подписей → тусклый для осей и хинтов.
- **Акцент (один):** красный/оранжевый в референсах. Применяется точечно:
  активный пункт nav, ключевая линия графика, выделенный сегмент, важная кнопка.
- **Семантика:**
  - зелёный — рост/успех/«в норме»,
  - красный — падение/нарушение/дефект,
  - жёлтый/оранжевый — предупреждение/промежуточное.
- **Графики:** заливки полупрозрачные, второстепенные серии — приглушённый серый,
  выделенная серия — акцентом. Сетка осей — едва заметная.

Для CCSA это ложится идеально: `--red` = нарушения/низкий балл, `--green` = высокий балл,
`--yellow` = средний. Акцентом дашборда логично сделать именно красный (тема качества/дефектов).

---

## 5. Типографика внутри дашборда

Контраст размеров — ключ к «приборному» виду:

- **Значение метрики** — очень крупное и жирное (28–40px), tabular-nums.
- **Заголовок метрики** — мелкий, приглушённый, обычно НАД значением (11–13px).
- **Дельта/тренд** — маленький чип рядом со значением: `↑ 12.5%` зелёным / `↓ 4.3%` красным.
- **Подпись-контекст** — совсем тусклая строка под значением
  («compared to last week», «From Jun 01 to Jun 29»).
- **Оси и легенды** — минимальный размер, тусклый серый.

---

## 6. Виджеты — как выглядят

Каталог визуальных типов, встреченных в референсах:

- **KPI-карточка** — иконка в цветном мягком квадрате, заголовок, крупное число, дельта-чип.
  Иногда мини-спарклайн на фоне.
- **Bar-chart** — столбцы с закруглённым верхом; выделенный столбец акцентом, остальные серые.
- **Line / Area** — плавная линия, полупрозрачная заливка под ней, точка-маркер с тултипом,
  часто пунктирная вертикаль на выбранной дате.
- **Donut / Gauge** — кольцо с крупным числом в центре («Total Defect 2,000», «86%»).
  Сегменты семантичны (дефект — красный, норма — серый/зелёный).
- **Heatmap** — сетка ячеек, интенсивность = насыщенность акцента (orders by time).
- **Dot-matrix** — ряды точек разного размера/цвета (blood tracking) для многомерных данных.
- **Список с превью** — строка: миниатюра/иконка + название + значение + статус-бейдж
  (production line status, top product, team members).
- **Таблица** — плотные строки, tabular-числа, статус-бейджи и цветные дельты в ячейках,
  строка hover-подсвечивается.
- **Горизонтальный прогресс** — набор баров с подписью слева и шкалой 0–100% (project completion).

Общее: у каждого виджета — единый мелкий заголовок и, при необходимости, компактный
контрол в правом верхнем углу (селектор периода «Monthly ▾» или меню «⋯»).

---

## 7. Микро-детали

Именно они дают ощущение «дорогого» дашборда:

- **Дельта-чипы** — стрелка + процент, цвет по знаку, мягкая подложка.
- **Селектор периода** — маленький `Monthly ▾` в углу карточки, а не отдельный крупный контрол.
- **Статус-бейджи** — «Processing», «Maintenance», «In Progress»: капсула с мягкой заливкой
  семантического цвета.
- **Иконки метрик** — в цветном скруглённом квадрате (soft-tint фон под цвет метрики).
- **Легенды** — точка-кружок + короткая подпись, компактно, справа сверху графика.
- **Тултипы** — тёмная плашка со значениями серий на наведении по графику.
- **Числа** — всегда моноширинные цифры (`tabular-nums`), разряды через разделитель.

---

## 8. Состояния

- **Hover** — строки таблиц и списков слегка подсвечиваются; карточки статичны (без «прыжков»).
- **Loading** — скелетоны в форме будущего контента (не общий спиннер на весь экран).
- **Empty** — приглушённая иконка + короткий текст по центру карточки.
- **Выделение/фокус** — акцентный бордер или мягкое кольцо, без резких теней.

---

## 9. Мобильная версия

Из первого референса (есть mobile-экран):

- Sidebar → нижняя навигация или бургер.
- KPI-карточки → сетка 2×N вместо ряда.
- Крупные графики → на всю ширину, вертикальный стек.
- Таблицы → карточки-строки либо горизонтальный скролл.

## 10. Светлая тема

Светлую тему нельзя получить «инверсией» тёмной — прямая инверсия даёт грязный,
контрастный экран. Нужен свой рецепт, сохраняющий то же «приборное» ощущение.

### Принцип

Тёмная тема строит глубину **свечением на тёмном**. Светлая строит её **мягкими
слоями серого на почти-белом** — как Notion / Linear / Stripe в дневном режиме.
Чисто-белый фон не используем: он «слепит» и убивает иерархию.

### Слои (светлота)

| Слой | Тёмная | Светлая |
|------|--------|---------|
| Фон страницы | почти чёрный | тёплый off-white (`--bg`, напр. `#f7f8f9`) |
| Карточка | на ступень светлее | **чисто белая** (`--surface`) — «поднимается» над фоном |
| Вложенный блок | ещё светлее | лёгкий серый (`--surface2`) |
| Граница | полупрозрачная светлая | тонкая серая `1px` (`--border`) |

Инверсия относительно тёмной: там карточка **светлее** фона, здесь — **белее** (ярче) фона.
Разделение слоёв в обоих случаях за счёт светлоты + тонкой границы, без тяжёлых теней.

### Глубина

- Вместо контраста фонов — **очень мягкая тень** у карточек
  (`0 1px 2px rgba(0,0,0,.04)`), чтобы белые карточки «отрывались» от off-white фона.
- Границы чуть заметнее, чем в тёмной (на светлом они читаются слабее).
- Тени — по-прежнему сдержанные: подчёркивают слой, а не «висят в воздухе».

### Цвет и семантика

- **Акцент** — тот же красный, но **чуть глубже/насыщеннее**: яркий неон со светлого фона
  выглядит кислотно. Для текста/линий берём затемнённый оттенок акцента.
- **Семантика** — те же зелёный/жёлтый/красный, но их `*-soft` подложки на светлом должны
  быть светлее и менее насыщенными (иначе бейджи «кричат»).
- **Графики:**
  - линии/столбцы — насыщеннее, чем в тёмной (тонкие светлые линии на белом теряются);
  - заливки под area — очень бледные (5–12% прозрачности);
  - сетка осей — светло-серая, почти на грани видимости;
  - второстепенные серии — средне-серые (не совсем бледные, иначе исчезнут).

### Текст

- Значения — почти чёрные (`--text-strong`), не чистый `#000`.
- Подписи — средний серый (`--muted`).
- Оси/хинты — светлый серый (`--faint`), но не бледнее фона.

Правило: контраст текста к фону в светлой теме нужно **явно проверять** — то, что читалось
белым на тёмном, в инверсии часто оказывается слишком бледным.

### Мини-палитра (ориентир, уже есть в токенах)

```css
/* light */
--bg:       #f7f8f9;   /* тёплый off-white — фон страницы   */
--surface:  #ffffff;   /* белые карточки                    */
--surface2: #f1f3f5;   /* вложенные плитки, треки баров      */
--border:   #e2e5ea;   /* тонкие границы                    */
--text-strong:#0d0e10; /* крупные значения                  */
--muted:    #5c6169;   /* заголовки, подписи                */
--faint:    #868c95;   /* оси, хинты                        */
/* акцент/семантика — чуть глубже, чем в dark */
```

### Чек-лист паритета тем

- KPI-число одинаково «весит» в обеих темах (размер/жирность).
- Дельта-чипы читаемы: зелёный/красный различимы и не блёклые.
- Выделенная серия графика видна в обеих темах.
- Донат/gauge: сегмент «норма» не сливается с фоном карточки.
- Границы и разделители видны, но не грубые.
- Скелетоны/hover/бейджи имеют светлый и тёмный варианты.

## 11. Что берём для CCSA (перенос)

| Из референсов | Наш эквивалент |
|---------------|----------------|
| Тёмный «приборный» фон | Полировка dark-темы; проектируем «от тёмной» |
| Один яркий акцент | `--red` как акцент дашборда (тема качества/нарушений) |
| Крупные значения + дельта-чипы | Уже есть `dash-kpi-value`; добавить тренд-чипы |
| Иконка метрики в soft-квадрате | Новый элемент KPI-карточки |
| Селектор периода в углу карточки | У нас период глобальный — оставить, но стиль подсмотреть |
| Donut/gauge, heatmap, dot-matrix | Кандидаты в новые типы виджетов (обсудим в составе) |
| Список с превью, статус-бейджи | Для «последних звонков», «топ операторов» |
| Плотные таблицы с бейджами | Уже есть паттерн в «Звонках» — переиспользовать |
